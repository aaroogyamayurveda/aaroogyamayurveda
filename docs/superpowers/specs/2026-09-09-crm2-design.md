# CRM2 Design Specification

## Goal
Build a zero-cost, production-oriented teleshopping business ERP at `/CRM2`, fully isolated from CRM1 and backed by a separate Supabase project.

## Architecture
CRM2 is a static web application using vanilla JavaScript and the Supabase browser client. Business rules that require trust boundaries live in Postgres RPC/functions with RLS. Integrations are adapter interfaces and are disabled until credentials are configured server-side. CRM1 remains untouched.

## Zero-cost constraint
Use only GitHub Pages/static hosting, Supabase Free-tier capabilities, browser APIs, and open-source/runtime-free dependencies. No paid SaaS, paid APIs, paid dialer, paid courier, paid WhatsApp/SMS, paid analytics, or paid automation is required for the core CRM2. Optional third-party integrations remain disabled unless separately funded.

## Core modules
Auth/RBAC, Dashboard, Leads, Customers, Calling (VICIdial-ready + manual mobile), Dispositions, Follow-ups, Orders, Verification, Inventory, Dealers, Delivery/NDR/RTO, Accounts, Imports, Reports, Audit, Settings.

## Security
Separate Supabase project `ukpfmlhkvwgoqrrgdump`; RLS on business tables; no service-role key in frontend; no private Drive data in GitHub; soft deletion by default; admin-only permanent deletion; audit events; restricted exports.

## Data model
Users/roles/teams, leads/calls/dispositions/followups, customers/addresses, products/warehouses/inventory movements, orders/items/status history/verification, dealers, couriers/shipments/events/NDR/RTO, payments/remittances/refunds/settlements, imports, audit logs, targets/notifications.

## UX
Fast login and lazy module loading. Agent workflow is Customer -> Call -> Disposition -> Follow-up or Order. Manager workflow is Company -> Team -> Agent -> Lead -> Order. Mobile/name/order/tracking search is first-class.

## Import
CSV/XLSX preview, mapping, validation, duplicate detection, import summary, soft-delete. Browser-native CSV import is core; XLSX is an optional adapter to avoid adding a paid dependency.

## Calling
Manual mobile calling is first-class. VICIdial/Asterisk uses an adapter contract with no credentials stored client-side.

## Acceptance
CRM2 can operate independently of CRM1, direct database access is RLS-protected, core CRUD/report workflows work, and no production module has duplicate versioned JS files.
